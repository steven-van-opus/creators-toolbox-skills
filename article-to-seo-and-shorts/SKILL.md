# Article to SEO and Shorts

Start with the published article, the site where the search version belongs, and any target social channels the user names. Read the source and note its practical takeaway, the facts that support it, and any examples worth retaining. Use the original text, a URL, or both. Keep source credit where the adaptation calls for it.

## Pick the search intent

Use the user's Google Search Console Queries and Pages export or fetch those dimensions through an authorized connection. Record the property, date range, and relevant filters with the evidence you use. Keep a filtered Queries export tied to the page filter it actually used. Separate property-wide Queries and Pages sheets do not establish which URL appeared for a query. If page association matters and the supplied sheets lack it, use a page-filtered query export or fetch query and page together.

Group close variants, then choose one target query whose intent the article can satisfy. Use related impressions, clicks, and the pages already appearing for those queries to make the choice. Impressions count how often the reported site or page appeared in Google Search. Use them as observed site evidence and never label them as total search volume. Explain in a sentence what the searcher wants to accomplish and cite the rows behind the choice.

If a site page already answers the same intent, adapt that URL. Use a new page when the evidence supports a distinct job for the reader. When there is no export or connection, ask for the relevant data and give an editorial hypothesis if the user wants a provisional draft. Label the evidence gap and leave all search metrics blank. Never invent queries as observed data, search volumes, or ranking forecasts.

## Draft the on-site article

Write a working title, SEO title, meta description, proposed or existing URL, and an H2 plan. Then write the CMS-ready draft. Answer the main question early and use the source's actual detail to show how. Rewrite for the searcher's task and use the target phrase where it reads naturally. Avoid stuffing the title, headings, alt text, or FAQ with keyword variants.

Suggest relevant existing internal links with their anchor text and where they belong. Flag a useful URL that still needs verification. Use secondary queries from the data to build a short FAQ when they ask distinct questions the article can answer. Include the real query behind each question in the editorial notes. When no verified query warrants an FAQ, leave it out. Keep the query evidence separate from the copy ready for the CMS.

## Plan the shorts

Plan one to three 9:16 videos. Give each short a different angle when the article supports it. Use a timed shot list with a talking head or authorized avatar above and a zoomed article excerpt or screen recording below. Start with a spoken hook, show one useful step or example from the article, and finish with one action that sends the viewer back to the on-site article.

Write the narration and matching timed captions. Keep captions and the key detail in the recording clear of channel controls. Check the crop and contrast at phone size. For a comment-keyword CTA, specify the word, who will fulfill replies, and the exact article URL. Choose an available link placement when the channel or team cannot fulfill comments. Use an authorized likeness and voice for an AI presenter and include the disclosure required by the destination platform. Verify the platform's current labeling rules when preparing a real upload.

## Hand off for scheduling

Give each video a channel, proposed date or relative slot and time zone, asset list, post copy, caption file or cues, disclosure instructions when relevant, and its destination URL. Note where that link will appear and carry any tracking parameters the user requests. Set slots after the article is live and mark missing assets or channel details in the handoff. This package can go to any scheduler, including Postiz. Keep it as a handoff unless the user asks to publish or schedule.
