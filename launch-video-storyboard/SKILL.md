# Launch Video Storyboard

## Write the result the viewer should see

Choose one action and result that can be demonstrated with the release build. List the source footage available, the product state needed for the capture, and the target length and aspect ratio. If the result exists only in an illustration, label it accordingly and avoid promising a live capability.

Build the sequence around the evidence shot. Decide what must appear immediately before it for someone to understand the change. Use the first shot to orient the viewer and the final shot to show one next action. Retain only context the viewer needs to understand the result.

## Give the editor exact beats

Use a contiguous timeline with start and end times. For each shot, specify what is visible, what changes within the frame, the production source or capture instructions, the exact text or narration, and optional audio cues. Mark hold time after each movement so the result and captions can be read. Shorten or split dense captions before trimming that hold.

Keep behavior continuous across shots, including cursor position, seeded sample data, and whether the viewer is the sender or recipient. When a transition explains a relationship, describe how it connects the objects. Use a plain cut when the next result already reads on its own. If you use references, record the lesson and its source, then design the sequence around your own assets.

## Check the timed cut

Read the storyboard in silence at intended feed scale. The viewer should know what changed, see evidence of it, and have time to read the closing action. Identify the source shot missing from the edit and any differences needed for a second aspect ratio. Keep validation concrete, such as “the viewer can identify the copied link and see the resulting board in the next shot.”
